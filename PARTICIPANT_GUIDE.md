# Participant Guide

## Workshop expectations

You are not graded on how much code you generate. You are evaluated on the quality of your architecture judgment.

A strong participant answer:

- identifies the real system boundary;
- distinguishes model capability from application authority;
- uses evidence rather than assumption;
- protects public contracts and data;
- defines failure and recovery behavior;
- limits blast radius;
- names owners and approval points;
- explains how the decision can be audited and reversed.

## Pair-work roles

For hands-on exercises, rotate between:

- Driver — performs the code or artifact work;
- Reviewer — checks architecture and risk;
- Operator — evaluates failure, telemetry, and rollback;
- Defender — presents the final decision.

## Before opening model answers

Every participant or team should first present:

1. the decision;
2. the strongest evidence;
3. the largest remaining risk;
4. the required control;
5. the rollback or stop action.
